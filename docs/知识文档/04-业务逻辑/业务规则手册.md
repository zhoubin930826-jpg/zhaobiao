# 业务规则手册

## 全局响应与错误处理

- 业务成功返回 `ApiResponse.success`，通常 `code=0`。
- 预期内业务失败使用 `BusinessException`。
- 很多业务失败 HTTP 仍是 200，前端必须判断响应体 `code`。
- 未认证、无权限等安全异常由 Spring Security 返回 401/403。

## 管理员认证规则

- 后台公开注册接口存在但业务上停用，返回“后台管理员不支持公开注册，请联系超级管理员创建账号”。
- 管理员登录要求用户存在、密码正确、状态可登录。
- `PENDING`、`REJECTED`、`DISABLED` 都不能登录。
- 登录成功写入 `lastLoginAt`。

## 管理员账号规则

- 只有 `SUPER_ADMIN` 能管理管理员账号。
- 管理员至少绑定一个角色。
- 管理员不能绑定 `NORMAL_USER`。
- 初始 `admin` 不能禁用，不能丢失 `SUPER_ADMIN`。
- 管理员状态只支持 `APPROVED`、`DISABLED`。

## 角色与菜单规则

- 客户侧授权模型是角色绑定菜单/按钮。
- 后端授权编码使用 `sys_menu.code`。
- `permissionIds` 只保留兼容，不参与当前角色授权。
- 内置角色不能删除，不能修改编码。
- 删除角色前必须没有用户引用。
- 删除菜单前必须没有子菜单，也没有角色引用。
- 旧权限接口和旧用户接口返回 410，不能恢复为主流程。

## 业务类型规则

- 业务类型编码和名称唯一。
- 编码保存时转大写。
- 只有启用中的业务类型才能被会员或招标绑定。
- 被会员或招标引用的业务类型不能删除，只能停用。

## 会员规则

- 门户注册开放，但注册后默认 `DISABLED`，不能直接登录。
- 门户注册必须上传营业执照和近三年业绩证明。
- 后台创建会员必须设置过期时间，并至少选择一个业务类型。
- 会员启用前必须有至少一个业务类型和过期时间。
- 会员登录要求状态 `ENABLED`、未过期、有启用业务类型。
- `expiresAt` 为空或不晚于当前时间都视为过期。
- 首次登录写入 `firstLoginAt`，响应 `profileCompletionRequired=true`。
- 会员删除是软删除。
- 手机号、邮箱、统一社会信用代码在未删除会员中唯一。

## 招标规则

- 新增招标固定为 `DRAFT`。
- 发布状态只能通过 `PUT /api/admin/tenders/{id}/status` 调整。
- status 接口只支持 `DRAFT` 和 `PUBLISHED`，不支持 `CLOSED`。
- 已发布招标不能编辑、删除、增删附件。
- 报名截止时间不能晚于项目截止时间。
- 发布时间不能晚于项目截止时间。
- 项目编号唯一。
- 招标必须绑定启用中的业务类型。

## 门户招标可见性规则

- 游客只能使用最新 3 条接口和详情接口。
- 游客最新 3 条不按业务类型过滤。
- 门户只展示 `PUBLISHED` 且 `publishAt <= now` 的招标。
- 会员列表按会员启用业务类型过滤。
- 详情正文公开给游客和会员，只要求招标已发布且发布时间已到。
- 附件下载严格要求会员业务类型匹配、可下载、未禁用、未过期。

## 资讯规则

- 新增资讯固定为 `DRAFT`。
- 发布状态只能通过 `PUT /api/admin/news/{id}/status` 调整。
- 已发布资讯不能编辑、删除。
- 门户只展示 `PUBLISHED` 且 `publishAt <= now` 的资讯。
- 最新资讯 limit 默认 6，最大 20。

## 文件规则

- 上传文件不能为空。
- 文件名会清理危险字符。
- 文件按 SHA-256 内容哈希去重。
- 图片和 PDF 生成真实缩略图，其他类型生成文件类型封面。
- 前端只能通过 fileId 调后端接口访问文件。
- 文件物理删除前必须确认没有招标附件、会员资料、资讯封面引用。

## 生产安全规则

- `prod` 环境必须显式配置数据库用户名和密码。
- `prod` 环境禁止使用 root 数据库账号。
- `prod` 环境禁止使用默认数据库密码 `root`。
- `APP_JWT_SECRET` 必须存在且至少 32 字符。
- 生产数据库变更不能只依赖 Hibernate `ddl-auto=update`，必须有 SQL 迁移脚本。
