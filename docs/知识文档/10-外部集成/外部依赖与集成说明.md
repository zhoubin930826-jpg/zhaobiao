# 外部依赖与集成说明

## MySQL

用途：

- 系统业务数据。
- 管理员、会员、角色菜单、招标、资讯、文件元数据和操作日志。

本地默认：

```text
jdbc:mysql://localhost:3306/zhaobiao_admin
```

测试默认：

```text
MYSQL_TEST_DB=zhaobiao_admin_test
```

注意：

- 测试依赖 Docker MySQL 8 或等价 MySQL。
- 生产不允许 root 用户和 root 密码。
- 生产变更必须执行 SQL 脚本。

## Aliyun OSS

用途：

- 生产文件对象存储。
- 原文件和缩略图都存储为 object key。

配置：

| 变量 | 说明 |
| --- | --- |
| `APP_FILE_TYPE=oss` | 启用 OSS |
| `APP_FILE_OSS_BUCKET` | bucket |
| `APP_FILE_OSS_ENDPOINT` | endpoint |
| `APP_FILE_OSS_KEY_PREFIX` | key 前缀，默认 `zb/files` |
| `APP_FILE_OSS_CREDENTIAL_MODE=access-key` | 使用 AK/SK |
| `APP_FILE_OSS_CREDENTIAL_MODE=ecs-ram-role` | 使用 ECS 实例 RAM Role |

安全建议：

- 优先使用 `ecs-ram-role`，减少长期 AK/SK。
- 不要把 bucket、AK/SK 或 JWT secret 写入仓库。
- 修改 key prefix 前要评估历史文件对象迁移。

## Nginx

职责：

- 托管后台静态文件 `/ztbgl/`。
- 托管门户静态文件 `/ztbfb/`。
- 代理 `/api` 到后端。
- `/` 可重定向到门户。

风险：

- 两个前端都是 history 模式，需要子路径刷新 fallback。
- 静态 base 必须与前端构建配置一致。

## systemd

生产后端应由单个 systemd 服务托管。

常见服务名：

```text
zhaobiao-admin.service
```

检查：

```bash
systemctl status zhaobiao-admin
ss -ltnp | grep ':8080'
```

风险：

- 不要同时运行手工 `nohup java -jar` 和 systemd。
- jar 版本变化时，`ExecStart` 也要更新到新 jar。

## Swagger/OpenAPI

用途：

- 开发调试接口。
- 给前后端核对接口路径和字段。

地址：

```text
/swagger-ui.html
/v3/api-docs
```

注意：

- Swagger 可作为字段辅助，但业务规则仍要看 Service 和测试。

## Captcha

验证码由后端内存服务生成：

- 场景：`register`、`login`。
- 有效期：5 分钟。
- 一次性使用。
- 大小写不敏感。

这意味着多实例部署时，如果没有共享验证码存储，注册/登录请求必须落到生成验证码的同一实例，或后续改造共享存储。
